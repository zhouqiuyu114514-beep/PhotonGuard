# 模态/QPM真实AI诊断与一次批准数值复验

沿用原工作台、WSL环境和累计20元账本。使用`--mode-ai`显式开启，源码绑定必须同时包含`mode_ai_extension`；旧薄膜授权绑定不能隐式接通新分支。密钥仍只在服务进程内。

## 当前流程与边界

1. 确认独立器件与QPM需求，选择规则或真实AI。相同页面、相同求解器和检查；AI模式明确同意发送有限任务/指标，不发送原始E/H数组或私有脚本文字。
2. 后台最多6个MPB worker完成基础/网格/计算域检查，真实AI根据已核验指标、模态身份和固定目标生成诊断。旧结果可直接诊断，无须重跑基础计算；每份证据最多一次请求，无自动重试或规则补写。
3. 一张卡列出位置、证据、独立数值候选的一项修改和资源。一份明确批准后自动复验，不再请求模型；失败与拒绝保留。结果可下载数值配方，原任意脚本没有被修复或执行。

开发阶段所有者已在2026-10-07明确授权Codex自主审阅并执行范围内的开发修复和复验，不逐项找本人审批。公开合成开发验收记录仍标`SIMULATED`，另外记录所有者的开发委托及Codex对具体卡片的审阅；不冒充最终用户点击，不把模型建议本身当批准。这不取消产品面向独立使用者的明确任务与修复确认。

锁定的mode_task包含器件、材料、波长、出处与初始数值种子。`mode-xcut-numerics-v1`候选单独保存，执行配方显式派生，不修改原锁。候选只能加密网格或扩大计算域，不能改长度、极化周期、截面、设计目标或独立验收器。资源允许值是上限约束，不是给模型的规则答案，也不是最优参数证明。

基础数值菜单最多80像素/μm，以实际两波长三设置计划估算文件与总输出，保持worker原32MiB文件上限、2GiB内存及总1800秒限制。输出估计上限768MiB且仍受整个工作区1GiB限制；容量不足时不启动、不放宽存储限制。修复前后再用场重叠及竞争模态核对身份，带号不作为身份。

## 解释与结果分别验证

`mode-qpm-diagnosis-1`只接受结构化有限claims。每条数值、单位、方向和JSON出处都重建校验；两种有限解释分别由实际证据校验：已测相位精度不足；锁定设计组合未达标。错误说明不能靠合法修改通过审计。

提出数值修改需要相关的实际超限比较以及同一位置的引用。QPM计算PASS但目标NOT_MET时，不可把改变制造参数当作修复。精度不足为INCONCLUSIVE，而不是设计FAIL；加密尝试不保证通过。全部返回均保存，包括REJECTED、FAILED和中断预留。

本实现保留原14次find_k科学校准与6次界面验收的旧源码绑定；后续真实AI和新复验另建记录。当前软件/协议回归已完成；真实联调结果以`local-validation/mode-ai-20261007/`独立记录为准，文档不预先宣称通过或AI增益。

真实联调初始两份输出将事实ID写入检查引用，原拒绝记录与费用保留。已增加精确引用别名：仅把已核验事实映射到其所属检查，记录每项规范化；不修改决策、数值、单位、修改路径或科学阈值。已保留返回可在新提交下显式离线重审，记录原请求/返回哈希、当前源码、事实表一致性与零新增请求。资料完整且精度已通过时，无超限依据的修复建议仍拒绝；不能因说明正确就执行不合法修改。

## 费用和启动

每次请求复用原累计账本、先预留最坏输入/输出，核验用量后结算。失败、未知用量及结算失败不释放预留。原20元与开发窗12次/5元叠加，源码升级不重置。

真实入口需先在干净已提交源码准备带`--research-stage --mode-ai`的绑定，然后启动`tools/serve_ai_repair.py --mode-ai --research-stage --binding <新绑定目录>`。旧工作台与已有服务继续复用；不会从文件恢复密钥。规则入口仍可使用`--rules-only --mode-qpm`。

本分支仍不计算绝对变频效率，不直接执行用户代码，不接入COMSOL，不将开发合成例当外部盲测结论。
