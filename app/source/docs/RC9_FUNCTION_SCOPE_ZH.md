# RC9 功能范围与使用边界

核心功能已按“AI 辅助、用户核对”的范围定型：三类受限理想光学模型中，从普通目标、明确采用的教学数据或 CSV 开始，经资料核对、AI 后续建议与受限计算，得到可继续分析和复跑的结果。

| 参与者 | 负责什么 |
|---|---|
| 程序导航 | 区分任务入口、展示条件表单、生成有限方案比较；从保存计划列出可行项与阻断原因，不冒充 AI 排名 |
| 用户 | 提供真实已知事实，确认教学条件、数值设置、数据来源与具体执行计划；可修改或停止 |
| AI | 提取有出处的条件、澄清缺项、解释已有证据、选择主要后续建议；不批准执行 |
| 数值工具 | 在已核对的模型和资源范围内实际计算，保存数据、计划、结果和失败；预测尺度不等于真实精度 |

超限方案不能执行。若 AI 仍把它作为主建议，保留该选择和阻断原因，另列标明程序来源的可行备选；用户可核对或停止，不自动补采。仅讨论改变条件时，可以解释超限方案，但不改变限制。

真实 CSV 等待新数据是正常状态。产品外合成 CSV 仍是测试资料；真实条件缺失时留待确认，不能套用教学默认或制造实测。少数语言提取失败可在公开表单补齐，不宣称任意中文全自动可用。

教学补采来自独立冻结对象。单膜候选数量减少只限当前搜索范围；参数变化不等于准确度提高。历史首批六条开发验收五条完成联合分析，另一条因开发并行调度锁失败，原方案另行恢复成功；定向复跑有一次超限主建议被拦截。各批次分别保留，开发操作者不算新增真人，未证明通用自主研究能力或普通 AI 普遍优势。

计算锁被占用时，本次尚未启动计算；保存数据、原结果及原预留额度。等待其他计算结束后，使用“另存设置版本”沿用数据，重新核对和批准；不自动请求 AI、补采或重试。

本地运行、依赖与许可见 [README](../README.md)，无界面复跑见 [三个现有反演入口](../examples/inverse/README.md)。保持 GPL-2.0-or-later 及数据各自的来源/许可。当前没有扩展为公网多租户、硬件控制或科研级精度认证。

开发时，将含求解的回归与用户旅程列在一个序列，按顺序完成，不同时启动。可用 `python tools/run_development_sequence.py stages.json`，其中每项含 `name`、`kind`（`read_only` / `solver_regression` / `user_journey`）和命令参数数组 `argv`。命令使用当前工作目录，任一阶段失败即停止；预检查锁只作提示，实际求解仍须原子加锁。该入口没有默认任务、费用授权或自动重试，不要并行启动多个序列。本轮只做离线检查，不重跑六条旅程。
