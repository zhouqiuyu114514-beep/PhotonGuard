# 受控对照的准备边界

当前已完成单膜、多层及公开合成模态/QPM开发闭环；运行期真实AI已接通，但没有受控证据证明AI优于规则。准备对照不增加模型请求。

## 已见开发例不能充当外部盲测

- 原单膜明确参数差异与网格修复是规则擅长的场景，不单独用它证明AI增益。
- 两份真实模态AI输出及32/48/64/80精度研究都已被开发者看见。两份原始拒绝、一次离线重审、一次AI建议执行和仍未通过的精度结果都进入记录。
- 64/80加密由Codex的有限数值研究计划选择，不归功于AI，不计为更多独立器件。
- 1000 μm案例继续标INCONCLUSIVE，不能调整目标或判据给某组制造PASS；短器件的PASS+NOT_MET也不是软件错误。

## 冻结前必须做到

1. 分别冻结运行源码、材料、任务协议、两类工具接口、资源计划和计价记录。软件测试、物理案例、内部求解数分开。
2. R、A、G共用当前三步页面、独立需求、实际观察、合法工具、模型版本及费用边界。A同样获得足够的物理说明和完整工具能力，不能故意给弱输入。
3. 协调资料放evaluation_private/，合法任务与观察放evaluation_inputs/；在模型调用前冻结哈希和评分器。模型不得访问标签、测试源码、预期修改或本计划。
4. 同一任务先记录原始首轮建议，再记录过滤/审阅卡及真实限定复验。解析失败、拒绝、未支持、超时、未达目标都留在相应分母。
5. 正式留出任务按冻结任务书的规模准备，先小批校验接口；既有inputs/coordinator包按其原角色保存，不能混入受测输入。当前还未发布新的24例留出集，也没有启动48次正式请求。
6. 模型只提出建议。开发审批可由Codex依据所有者委托审核具体冻结卡，仍标SIMULATED；真人试用另记，不能把开发自动运行算成人工使用时长。

## 费用与结果口径

现20元总账不变，累计30次、保守占用4.203874000030元；开发窗最多12次/额外5元已用3次。正式评测需要单独记录版本/任务/请求计划并叠加同一本账，不能清零或沿用开发窗假称有48次额度。每次仍先预留约2.12992元最坏费用，失败与未知用量保留；旧授权与源码绑定不得绕过。价格过期先在线重核，不在页面加载时派发。

结果报告至少区分正确诊断、合法修改、解释依据、实际复验、正确停止/覆盖率、错误放行、正常案例误改、请求与求解器成本。不把全部拒绝当作全部安全成功；不把过滤后安全卡冒充原始模型准确率。没有人工基线不写节省人工时间，样本不足标探索性。
