# Supported-input and execution boundaries

The application executes only a strict, finite JSON parameter adapter. A later read-only AST importer recognizes an exact sequential Meep flux-acquisition subset and performs only bounded finite arithmetic on constant expressions. It never executes imported Python, imports its dependencies, uses eval, claims arbitrary-program equivalence, exposes a shell to a model, or runs unreviewed ZIP code. The original source bytes, SHA-256 and line mappings are retained; complete extraction and independently confirmed task intent are required before the trusted recipe can run. See IMPORT_LIMITATIONS.md for exact scope. Unknown fields/models are stopped rather than silently coerced. Missing material intent produces INCONCLUSIVE. An epsilon value of2 is legal; only its disagreement with an explicitly confirmed n=2 task is a task mismatch.

Each run requires the task and frozen-policy hashes to match an explicit confirmation record. The target uses candidate parameters; tmm uses the separately locked task at the actual Meep frequencies. The source/monitor/domain recipe is generated by reviewed code. Every numerical study makes its own fresh reference pair; no cross-grid field cache exists.

The solver worker receives only selected environment variables and JSON data. CPU time, virtual memory, output size, open files and walltime are capped. One serial worker runs at a time; a complete case permits at most8 FDTD simulations. The runner records completed-pair counts separately from conservatively reserved attempted runs, because a crashed worker may have started simulations without completing its raw report. The resource wrapper is defense in depth, not a complete security sandbox against hostile native code. Only the bundled reviewed worker is run.

The UI is read-only and loopback-only. It does not expose run/mutate/upload endpoints. It escapes HTML, checks Host and path boundaries, refuses symlinks and does not load remote assets. Do not expose it through a public tunnel.

A proposal contains one structured change and is not an authorization. Explicit CLI `apply --approve` is required. The apply validator separately enforces task/candidate/policy hashes, allowed paths, allowed values and maximum two rounds. Physics restoration may only use the locked task. Numerical increases remain bounded; model-proposed policy, reference, source-code or tolerance changes are rejected. A changed candidate has no PASS until fresh mandatory checks finish.

Raw fluxes are not clipped, re-normalized to unit energy, filled from tmm, masked or filtered. Missing/weak/nonfinite frequencies stop acceptance. Unequal completed stop durations are not automatically wrong: the valid shorter-reference regression tests that nuance. Same source waveform/phase/grid pairing is still essential.

The DeepSeek-compatible transport is implemented but no live provider is configured or called in this checkpoint. Missing approval or credentials blocks before the network. A persistent ledger reserves worst-case cost before every attempt and preserves failed-attempt reservations. The unconfigured backend throws an explicit error. Rule-derived explanations and repairs are labeled rules_only and actual_llm_calls=0. Any future provider must record actual model/version, full tool/context budget, requests/responses, usage and costs; same-model controlled evaluation remains future work.
